# Phase 7: Implement atomic JEV and real Advisor synthesis

## Overview
Implement a runnable H candidate, not merely a report or renamed heuristic. JEV handles focused semantic relations; a genuine independent read-only reasoning agent synthesizes obligations/integration; deterministic code owns policy and effects. Coverage C01–C03/C08/C27/C34. M remains the production comparator until phase8/9 selection.

Context: [atomic design](../261019-jev-atomic-review/phase-02-shadow-evaluation-of-atomic-judgments.md), [fresh online verification](./research/jev-atomic-online-verification.md), C01–C35 coverage and council ADR. Official documentation supports focused primitives/batching, not local superiority.

## Requirements
- Keep meaningful todos. Decompose semantic questions/evidence, not every command into a native microtodo.
- Code computes exit status, identity, hashes, schema/coverage and exact comparisons. JEV receives one bounded semantic relation per question; related counterevidence stays visible.
- Batch only independent questions sharing coherent state; dependent retrieval/judgments create a new explicitly bound packet. No one-request-per-claim default, probabilistic independence assumption or pass-score averaging.
- Preserve immutable independent Advisor/JEV results. A reasoning receipt is not human authority, evidence completeness or native commit.
- Parent acceptance requires original criterion coverage and separate applicable integration evidence/review; all children passing is insufficient.
- Build the complete real candidate even if later adoption is rejected. No fake provider, report-name authentication, parent-pasted assessment or source mock fallback.

## Architecture
Add `src/atomic-judge.ts` using the existing shared client and phase2 packet builder. Planned `PredicateSpec` binds criterion/question IDs, one claim, evidence/counterevidence refs, applicability and answer type. `AtomicReviewReceipt` records contract/evaluated-tree/packet/rubric/policy digests, requested/resolved model, typed outcomes and actual usage/attempts when returned. Missing or contradictory proof yields explicit insufficient/contradicted outcomes; a selected excerpt never proves global absence. Execute multi-packet JEV work outside the22-second native preflight into bound receipts, alongside the existing non-authoritative review preparation path; native stage revalidates/composes, never serially waits for an unbounded predicate batch.

For real reasoning, use two cohesive modules: `src/advisor-protocol.ts` (types/binding/validation/journal fold) and `src/advisor-runtime.ts` (factory-owned supported-host adapter/state machine). The extension creates a request; the parent executes the actual native task schema with an advisor item; host-observed successful terminal native output produces an immutable bound receipt. **Choose supported `blocking:true` project Advisor definitions as the initial complete implementation.** Reasoning runs across turns, outside the22-second native mutation preflight; no async framework is required.

Pinned host18.12.2 sources inspected by the design advisor expose `on`, `registerTool`, `sendMessage`, `appendEntry`, `events`, `ctx.agent`, session history and subagent lifecycle/progress. These are source-supported APIs, not live-hook proof: [extension types](https://github.com/can1357/oh-my-pi/blob/v18.12.2/packages/coding-agent/src/extensibility/extensions/types.ts), [task outputs](https://github.com/can1357/oh-my-pi/blob/v18.12.2/docs/tools/task.md#outputs), [lifecycle payloads](https://github.com/can1357/oh-my-pi/blob/v18.12.2/packages/tui/src/overlays/session-observer-registry.ts#L9-L40), [delivery semantics](https://github.com/can1357/oh-my-pi/blob/v18.12.2/docs/extensions.md#message-delivery-semantics). ## Implementation Steps
1. Implement actual criterion→deterministic-check/semantic-predicate mapping and original parent coverage. Source spans include text plus digest and bounded counterevidence; record omissions. No generated criterion can silently replace an original obligation.
2. Implement coherent grouping and a finite manifest before allocation under shared count/byte/context and whole-semantic-review policy. Prepare through the existing explicit verifier/review path outside native preflight; consume packets lazily, honor deadline/cancellation and retain uncovered obligations on exhaustion. Existing transport is the sole retry owner. Use typed supports/contradicts/insufficient relations or explicit Noul propositions and validate every result; raw Noul/confidence remain separate. Stable question IDs contain no raw secrets.
3. Expose the runnable candidate through a real local evaluation seam `evaluate(strategy,input,shadowContext)` consumed by phase8, plus intended project tools. Shadow explicitly forbids todo/plan mutation and authority reuse; do not simulate the H driver with `evaluateAdvisorIntent`.
4. Create a host-owned namespaced request using phase1's discriminated consultation/task_review/parent_review binding. Consultation requires no todo and is never eligible for native staging; task/parent modes require exact contract/incarnation/logical-operation/target, parent session/request anchor, evidence/tree/test/policy and parent/child/integration digests. Distinguish the actual reasoning dispatch parentToolCallId from the later fresh native mutation call ID. Bind authorized evidence paths/internal-resource identities, default search roots, automatically injected context and egress policy into the request. Missing review returns an executable pending request, not a fabricated approval.
5. Before any provider execution install child-bound default-deny hooks. Identify the actual host child through `ctx.agent` kind/ID/name/parent linkage, not its prompt/frontmatter; use real tool_call blocking results. Source-supported getAllTools/getActiveTools/setActiveTools can clamp/check registry, but keep mediation for later additive tools. Parent dispatches the actual native `tasks:[{agent:"advisor",...}]` shape with the expected structured schema and a source-supported blocking definition. Validate parentToolCallId/item index and actual allocated child ID; subscribe before dispatch, capture session epoch and do not confuse requested name with allocation.
6. Accept sync output only when the **outer actual task envelope is not isError**, matching `SingleResult` has exitCode0, no aborted/error, expected schema metadata and locally valid final assessment. Executor yield/progress/completed lifecycle is provisional: in host18.12.2 a later isolation/patch wrapper failure can preserve a zero-exit child while returning isError. Async acknowledgment/results[] or completed bus frames never settle the initial blocking-only protocol. If async support is later intentionally added, additionally join the real acknowledged (possibly collision-adjusted) job ID and successful host-owned terminal job/envelope to the same request/child/parent/session identity; fail closed when missing, ambiguous or evicted. A status snapshot alone never supplies the assessment.
7. Canonical-copy/freeze the validated assessment only after native-task finality, persist digest/provenance and enqueue at most one parent continuation with supported nextTurn/triggerTurn delivery. Actual output includes verdict, concrete recommendation, ranked options, findings, confidence, open questions, criterion coverage and parent integration assessment. Initial review does not receive JEV verdict as its desired answer. Incremental/useLastTurn/schema-overridden output, conflicting terminal delivery, failure or abort cannot become a valid receipt.
8. Mediate every actual call at argument level: guarded canonical read/grep/glob roots and internal-URI identities, defaults, link escapes, private home/config/session/agent/history resources and initial context/packets. Reuse phase4's authorized guarded buffers; a readonly name is not read permission. Disable web_search by default for frozen local review; separately authorized public-only minimized queries must contain no protected source. Block Bash/Eval wrappers, nested task/eval spawns, write/xd devices, edit/mutation and recursive TypeSafe/Advisor tools. Host context outside authorized scope or missing guard capability prevents assessment acceptance before disclosure; never fall back to declared tools. Hooks are not an OS sandbox.
9. Rehydrate active-branch request/receipt history without losing reviews on ordinary turn end; invalidate transient native stages. Branch rewind, foreign session, changed evidence/test/contract/policy or task reincarnation invalidates applicability. Late callbacks and conflicting duplicate terminal outputs fail integrity validation. Fresh unrelated sessions cannot import permission from JSON.
10. Parent submits a fresh native call for the same logical operation after required semantic/reasoning work. Within the short preflight, revalidate current contract/evidence/policy, exact typed JEV/Advisor receipts and phase3 composition; do not perform the multi-packet HTTP loop there. Missing/stale receipts return actionable review_required/evidence-required without invented semantic failure. Stage only the allowed disposition; matching native result still commits. Request IDs/digests are correlation, never authorization.
11. Keep the initial implementation blocking-first: enable supported `blocking:true` in the project definitions before dispatch and consume the real terminal envelope/SingleResult. If an actual host returns an unsupported async acknowledgment, reject its receipt and require a correctly configured new real dispatch; never accept completed executor frames, pasted prose or an invented provider. No reasoning is awaited inside native preflight. Stronger cryptographic loaded-definition attestation is not supplied or falsely required.
12. Implement distinct parent review over the original parent contract, child receipts, uncovered obligations and real compatibility/integration evidence. All unit/child passes with a writer/reader protocol mismatch or missing integration proof must still block parent completion.
13. Route actual Advisor/expert reasoning roles through this engine and remove heuristic-as-Advisor/fake-agreement paths; retain cheap intent heuristics only as explicitly labeled signals. Do not spawn redundant reviews for identical applicable snapshots or require human review merely because a plan is long.
